One set of weights, applied again and again.

01 / The model in one sentence
Mental model

A looped transformer is a stack of Transformer layers that you apply to its own output K times during the forward pass, so the same small parameter set pays for K steps of computation instead of K independent layers.

02 / The mental model

Two ways to go deep.

On the left, the classic recipe: stack K independent Transformer layers, each with its own weights. On the right, share the weights and unroll the loop K times. The right side has K steps of compute and one block of parameters.

03 / Walkthrough

Six things to actually know.

FIGURE 2: The recurrence relation. xₖ is the entire sequence of token representations.

The hidden state is the token sequence.

In a normal Transformer, each layer reads from a key/value cache of everything before it. In a looped Transformer, there is no cache. The same K layers are stacked, but each layer shares weights with the others, and the activations of the bottom are fed back in at the top. The "hidden state" that gets updated is just the sequence representation itself.

Formally, with one stack of F layers the recurrence is xₖ₊₁ = F(xₖ) + xₖ, same residual trick as ResNets. The Universal Transformer (Dehghani et al., 2019) was the early version; Looped Transformers are the modern, better-tuned descendant.

Same weights, different work per loop.

If the block is literally the same function at every step, why does the model get stronger with more loops? The hidden state entering each loop changes. So the input distribution to the shared function shifts, and the same parameters end up computing different operations.

A Sep 30 paper, Shared Weights, Selected Computations, shows this is exactly what looped models learn to do on graph-walk tasks: a frozen block can be steered to a different transition just by editing its entering hidden state. The hidden state is what "routes" the shared block.

FIGURE 3: The shared block reaches A, then B, then C. Only the input distribution changes between calls.
FIGURE 4: Adaptive Computation Time. Easy prompt exits after few loops, hard prompt keeps looping.

Loop count can become a per-sample knob.

Once the model is a recurrence, you can give it a learned halting head that decides when each token has done enough loops. ACT-style loop transformers spend compute proportional to how hard the sample is, instead of spending the maximum on every token. That is the same trick that powers things like the "thinking budget" in reasoning models.

It also makes inference-time scaling free of extra weights: you can run the same checkpoint 3 times or 30 times and pay only for what you used.

The first joint recurrence-and-sparsity scaling law.

Scaling laws used to treat two efficiency axes separately: deeper (more layers) and wider (more experts per token). The Sep 30 paper Scaling Laws for Looped Mixture of Experts (Chen, Goyal, Krishnamoorthi) closes that gap.

Its Loop Scaling Law has a bounded, sparsity-conditional recurrence term that predicts how many loops pay off under different sparsity levels. Concrete payoff is roughly 3x active-parameter efficiency from sparsity and roughly 2x total-parameter efficiency from recurrence, and joint scaling pushes the frontier further. At trillion-token training, a looped MoE matches a non-looped MoE twice its size on the same compute budget.

FIGURE 6: Memory decomposition: the looped model trades KV cache for a fixed-size activation footprint.

Memory shapes where loops win.

A looped model has no KV cache. The recurrent state lives inside the same forward activations you would have computed for a feedforward pass anyway. That is the entire reason anyone cares about this for inference. Standard attention grows memory linearly with sequence length; the looped version's activation footprint is bounded by K times the block size.

It also generalizes to longer sequences at inference than it saw at training, because the recurrence is position-agnostic by construction. Standard Transformers lose cross-position generalization; looped ones do not, which is why they keep showing up in length-generalization benchmarks.

Where loops lose, and where they win.

Loops buy you two things and cost you two things. They buy compute depth at fixed parameters, and length generalization. They cost wall-clock time per token (K sequential forward calls are not free), and they cost peak memory if you backpropagate through the unroll naively (you checkpoint aggressively).

The cost equation flips if you have a custom kernel that fuses the loop, if you only unroll at training time and checkpoint aggressively, or if your workload is throughput-bound and length generalization matters more than first-token latency. Most production looped transformers train with a smaller K and at inference use looped inference only on long-context or reasoning workloads.

04 / Common confusions

Four things people get wrong.

1
"A looped transformer is just a deeper transformer."

No, it is shallower in parameters and equal-or-deeper in compute. The shared weights are the entire point. If you unrolled the loop into K distinct layer instantiations, you would not get a normal transformer, you would get a weight-tied one with different training dynamics and worse loss.

Right: depth comes from sequential compute, not from parameter count.

2
"Looping is the same as recurrence in Mamba or RNNs."

Close but not the same. Mamba has a fixed, hand-designed linear recurrence over a single state. A looped transformer has an attention-based recurrence over the entire sequence representation. The state is high-dimensional and structured; updates happen through attention, not through a learned matrix-vector product.

Right: same shape, different state object. One is a vector; the other is a sequence of token vectors.

3
"Looping is cheap because the weights are reused."

Parameter math is reused; the activations of every loop must be materialized for backprop. Naive loop training stores K activations and OOMs fast. Production implementations either unroll with gradient checkpointing, truncate BPTT to a few steps, or use a custom kernel. The "loop is free" framing is wrong in both directions.

Right: parameter FLOPs are reused, activation memory is not.

4
"GPT-6 / Astra / Looped Transformers means looping replaces attention."

The recent HN discussion conflates "looped transformer" with "looping as a substitute for attention layers." Most published looped models still use attention inside the block. The loop is over layers, not over attention heads. The competition is between depth strategies, not between recurrence and attention.

Right: the loop is a depth schedule. Attention still runs inside each unroll.

Three places to keep digging.

Paper
Scaling Laws for Looped Mixture of Experts

Chen, Goyal, Krishnamoorthi. Sep 30, 2026. The first scaling law that puts depth, MoE, and parameter count on one axis. 2x which is a 2x total-param efficiency from looping in closed form.

Wu, Hu, Zhang. Sep 30, 2026. Activation-patching evidence that the hidden state, not the shared block, routes what each loop computes. Has code on GitHub.
