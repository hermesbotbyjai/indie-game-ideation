Transformers are memory stores in disguise.

A linear layer holds about as many facts as its key dimension. An MLP holds tens of times that. Softmax attention holds over a million. The whole transformer architecture is an answer to a single question: how do you pack more memories into the same number of weights without drowning recall in interference?

The model in one sentence

The whole transformer is a sequence of memory stores, each one trading write cost and parameter count for more facts of the past it can recall cleanly.

Read it once

Every block writes a bank of key-value pairs into its weights or activations, then at query time returns a weighted sum of values where the weights are key-query similarities. Hebbian outer products, ridge regression, an MLP, and softmax attention are all answers to the same capacity problem, with each next one suppressing interference more aggressively than the last.

The mental model

Four memory stores. One capacity ladder. The same recall equation.

Every store below answers f(x) = ∑i vi · σ(ki² · x). What changes is how the memories are written (the matrix construction) and which nonlinearity σ is used. The capacity numbers below come from running each store with dk = 64 unit keys and counting when interference meets signal.

The walkthrough

From a matrix of correlations to a nonparametric recall table.

1. Hebbian outer product: storing is the easy part.

The simplest associative memory writes a memory by adding an outer product to a weight matrix. For a key-value pair (ki, vi), the rule is W ← W + viki². To recall, you query with x and read out f(x) = Wx = ∑i vi(ki²x). This is the same update rule a gradient step takes, and the same state that linear attention uses for its recurrence. Memory writes and model updates are the same operation.[1]

The catch: every key you store adds interference to every recall. For random unit keys in dk dimensions, the interference-to-signal ratio climbs like √(M/dk). Cross 1, and recall fails. That happens at M ≈ dk, sixty-four memories at the dimension we are working with.[1]

Why this matters

Hebbian storage is what makes fast weights, linear attention, and Modern Hopfield networks feel like the same idea. They differ in when and where the outer products are added, not in the math of the write. They all share the same ceiling on capacity.

Red bar is the recall for the stored key. Grey bars are interference contributions from every other stored memory. Together, they sum to the recalled vector; once the envelope of interference meets the signal, recall fails.

Raw keys cluster along a few shared directions, so a query that matches one cluster over-weights many similar memories. The pseudoinverse (K⊤K)⁻¹ strips that covariance so each stored memory gets a fair voice in recall.

2. Whitening the keys doubles your capacity.

The Hebbian store writes each memory without looking at the others. The optimal linear store solves for W as a least-squares fit over every stored key-value pair at once. The closed form is W = V²K(K²K)⁻¹. The extra factor (K²K)⁻¹ whitens the keys: it cancels the directions that many keys share, the directions that create correlated interference during recall.[1]

Up to M = dk, the optimal store has zero interference. It then climbs like the Hebbian store but with a −1 subtracted under the square root: ‖interference‖/‖signal‖ ≈ √(M/(dk−1)). That single correction is worth a factor of two in capacity, from M ≈ 64 to M ≈ 128. Past that, the two stores converge.[1]

Why this matters

Linear regression on keys is not just a math trick. It is what every "ridge regression" memory layer, every least-squares meta-learner, and every test-time regression paper is approximating. The whitened store is the linear ceiling; everything past it has to spend nonlinearity to break through.

3. A ReLU is a recall sharpener, not just a squiggle.

Linear stores cannot suppress low-similarity memories because their recall weights scale small and large similarities by the same factor. Insert a nonlinearity σ and you get f(x) = V²σ(Kx). A ReLU zeroes negative ones; a ReLU squared pushes positive ones up; a softmax turns the largest similarity into the only thing that matters.[1]

The ReLU effect is the easiest to quantify. For random keys, a similarity is equally often positive or negative, so ReLU zeroes about half the recall weights. Halving the variance of the weights shrinks the interference by √2.[5] Stack two ReLUs in sequence (the standard MLP nonlinearity is ReLU²) and the capacity gain compounds. At dk = 64, you go from ~128 memories for the optimal linear store to about 2,700 for the MLP. Twenty times the capacity, same parameter count.[1]

Why this matters

This is the cleanest argument for why MLPs are not throwaway components in modern transformers. The MLP layers are doing memory work that attention alone cannot, because attention keys are limited to dhead per head. MLPs store the long tail of facts that no single attention head can hold cleanly.

All three curves assign recall weights to the same set of keys, sorted by similarity to the query. Linear hands a non-zero weight to every key. ReLU zeroes the negatives. Softmax kills everything except the top few. Each step concentrates recall on a smaller, more reliable set of memories.

Attention does not store keys in W. It stores them in the activations of the current context window. The number of memories M is whatever the context length is. That is what "nonparametric" means: adding memories does not change the parameter count.

4. Softmax attention is a nonparametric memory store.

The first three stores write their memories into the weights. Softmax attention does not. Every token in the current context is a key-value pair in the activations, and the recall is just softmax(QK²) V. Adding a memory to the store costs zero parameters; you just append a token. Adding a memory to a parametric store costs a row of weights.[1]

The capacity bound is different too. Modern Hopfield analysis shows that as the key dimension grows, the capacity of a sharpened softmax scales like exp(c · dk), which blows past any polynomial bound a parametric store can hit.[2] At dk = 64, that puts soft-attention capacity comfortably past a million memories, and at dk = 128 it is many orders of magnitude higher. The cost is the activation memory: every context token has to live in HBM during the forward pass.

Why this matters

This is the architectural reason context windows matter and the architectural reason they are expensive. Each new token is another entry in the in-context associative memory, and every query touches all of them. Long-context inference is a long-context recall table, not a "longer thought". KV-cache compression, sparse attention, and sliding-window tricks are all attempts to make that table smaller without losing recall.

5. A gradient step and an outer-product write are the same operation.

For a linear layer y = Wx with scalar loss L, the gradient with respect to W is ∂L/∂W = (∂L/∂y) x². A gradient step with learning rate η is W ← W − η(∂L/∂y) x². That is an outer-product memory write with key x and value −η(∂L/∂y).[1]

Read this way, training is not "adjusting knobs to reduce loss". It is "iteratively writing a bank of associations into W, one training example at a time, where each example pairs an input with the desired response". Inference, the forward pass, then becomes a content-addressable lookup against that bank. Irie and colleagues made this exact argument formally and showed a linear layer is equivalent to attention over all its training inputs.[1]

Why this matters

If a gradient step and an associative write are the same, then continual learning, fine-tuning, and in-context learning all become the same problem with different write schedules. The fast-weight line of research, all the way to modern Hopfield and Titans-style persistent memory, is doing the same algebra with different storage media.

Hebbian outer product (top) and gradient descent (bottom) are the same algebra with different sources for v. Treating training as iterative memory writing changes what "fine-tune" and "in-context learn" mean.

Common confusions

Four things people get wrong about this picture.

Confusion 01

"Linear attention has the same capacity as softmax attention."

Linear attention is an outer-product memory store with capacity ~ dk.
Softmax attention is a sharply-nonlinear memory store with capacity that grows exp(c·dk). The nonlinearity is not a tweak, it is the difference between dozens of memories and millions.
Confusion 02

"Attention is just mixing token embeddings."

Attention is a linear combination of value vectors weighted by token-token similarity.
Attention is content-addressable recall. The values are the things you are trying to remember, the queries are what you are trying to remember them for, and the keys are how the memory store decides if a stored memory matches the query.
Confusion 03

"Bigger models remember more because they have more parameters."

Capacity grows linearly with parameter count.
Parametric capacity grows with the rank of the recall matrix, which is bounded by key dimension. The model picks up the rest by storing memories in activations (context) and by stacking stores, not by adding parameters to a single store. A 70B model and a 7B model have the same per-layer capacity, the 70B has more layers.
Confusion 04

"KV-cache compression throws away memories."

KV-cache compression reduces recall fidelity by evicting keys.
Good KV-cache compression picks keys with low interference, which is exactly the set of keys that were contributing the least to recall anyway. The capacity budget is bounded by interference-to-signal ratio, not by token count. You can usually halve the cache with negligible recall loss if you pick the right half.[1]
