Day 2. Inference

Speculative Decoding.
how LLMs go brrr without going wrong

A staff-level walkthrough of the trick that cuts LLM serving cost by 2x to 5x while keeping the output bit-for-bit identical to a slow decode.

  • Why autoregressive decoding is the actual bottleneck in production
  • The draft-then-verify algorithm and why it stays lossless
  • How EAGLE-3, DFlash, and DSpark each attack a different bottleneck
  • What to measure in your own serving stack to know if it will pay off
Model in 1 sentence

A small, fast draft model guesses the next γ tokens, the big target model verifies the whole block in one parallel forward pass and accepts only the tokens that match its own distribution using rejection sampling.

The Mental Model

The slowest part of an LLM is not the model. It is the loop.

Every chat you have ever sent to an LLM produced exactly one token per forward pass through billions of parameters. The math is sitting there idle most of the time.

Vanilla decoding leaves the GPU idle between tokens. Speculative decoding batches verification across multiple draft tokens in parallel.

The wall-clock cost of generating N tokens is dominated by N sequential forward passes through a 7B–400B parameter model. Each pass costs the same whether the next token is the closing brace of a JSON block (trivially predictable) or a rare proper noun (very hard). Speculative decoding exploits that imbalance: cheap draft model handles the easy tokens, expensive target model only steps in to verify.

Walkthrough

Six things you actually need to know

01 / THE BOTTLENECK

Autoregressive decoding is one token per pass.

For a 70B model on a single H100, generating 1000 tokens takes roughly 30 seconds at ~33 tokens per second. The arithmetic intensity per token is high, but the dependency chain is serial. You cannot generate the 100th token without first generating tokens 1 through 99, and you cannot start pass k+1 until pass k finishes. The GPU is doing useful work, but it is doing it in a chain.

Throughput scales with batch size and with cheap tokens. Latency is bounded by the chain length and by the wall time of each forward pass. Speculative decoding attacks latency by breaking the chain: produce several tokens per chain link.

Why this mattersEvery LLM API you have used has been rate-limited by this chain. Multi-token parallelization is the only way to cut it without changing the model weights.
02 / THE TRICK

Draft γ tokens cheaply, then verify in parallel.

A small draft model. typically 1/20th the size, same tokenizer, same vocabulary. generates γ candidate tokens autoregressively, the same way the big model would. Each draft token costs ~5–10% of a target forward pass.

The target model then takes the whole proposed block plus the prefix, and runs one forward pass that scores every position in the block in parallel. The KV cache for the prefix is reused; the new attention only touches the γ draft positions.

The cost of one target forward pass over γ tokens is roughly the same as over a single token, because matrix multiplies are bandwidth-bound and the KV cache for the prefix is already on chip.

Why this mattersOne target forward pass amortized across γ tokens is the entire economic case. If you can score 4 tokens for the price of 1, every other constant matters less.
03 / THE MATH

Rejection sampling is what makes it lossless.

This is the non-obvious part. The draft model is wrong sometimes, so why doesn't the output drift? The answer is that acceptance is decided by the target model's own distribution, not the draft's.

Concretely: for each draft token x_i, compute p = p_target(x_i | prefix) and q = p_draft(x_i | prefix). Accept with probability min(1, p/q). If the draft is more confident than the target, it accepts almost always. If the draft is less confident than the target, it sometimes rejects.

When a rejection happens, sample a replacement from a corrected distribution and stop the block. This correction exactly preserves the target distribution: across all possible draft proposals, the verifier's accept-or-resample rule makes the marginal distribution of every output token identical to plain greedy / sampling from the target.

The expected number of accepted tokens per round depends on how well the draft distribution matches the target. A 7B draft targeting a 70B model averages 2–4 accepts per block on chat data, which is enough for a 2x–4x speedup at low draft cost.

Why this mattersLossless means you can flip the switch without retraining, without re-evaluating, without telling downstream users. It is the only inference optimization that ships for free.
04 / THE COST MODEL

The speedup is τ × (T_draft + T_verify), not just T_verify.

Three numbers matter. T_draft is the wall time to produce γ draft tokens. T_verify is one target forward pass over the prefix plus γ new tokens. τ is the expected number of accepted tokens per round.

If your draft is too big, T_draft eats the savings. If your draft is too dumb, τ collapses and verification dominates. The optimal draft size depends on the model pair: for a 70B target, a 1B–7B draft usually wins. For a 400B target, a 30B draft can pay for itself.

On Qwen3-8B serving a single request on a B200, vanilla decoding produces ~230 tokens/second. With a DFlash draft model, that climbs to ~630 tokens/second on conversational text, roughly 2.75x. Math is a different story because rare numbers are hard to predict and τ drops.

Why this mattersIf you cannot measure τ on representative traffic, you cannot know whether speculative decoding will pay off in your stack. A 1.1x speedup is a write-off; a 3x speedup changes your unit economics.
05 / THE FOUR GENERATIONS

Each generation attacks one of T_draft, T_verify, or τ.

Lossless speculative decoding is from 2023. The interesting work since then has been incremental, and it is worth knowing which lever each one pulls.

EAGLE / EAGLE-3 (NeurIPS 2025) makes the draft itself a feature-fused head on top of the target, so its hidden states match the target's. Higher τ, same verify cost.

DFlash (ICML 2026) replaces autoregressive drafting with a parallel diffusion block: produce the whole γ-token block in one shot. Lower T_draft, slightly lower τ.

DSpark (DeepSeek, 2026) builds a custom verification kernel that fuses the rejection-sampling check into the target forward pass. Lower T_verify, same τ.

DFlash 2 (Inco AI, 2026) combines a larger acceptance head with a smarter verifier. The arms race is still open.

Why this mattersIf you only have time to follow the field, follow τ and T_verify. T_draft is already saturated by parallel drafting, and most of the next 10–20% gains will come from squeezing the verifier kernel.
06 / WHEN IT DOES NOT PAY

The amortized case breaks for long-form math, code with unique identifiers, and tiny batches.

Speculative decoding assumes the target's verification pass costs about the same as a single-token forward pass. That assumption holds for the prefix, but the γ new tokens add KV cache writes that are not free on memory-bound hardware. If γ is too large for the available HBM bandwidth, T_verify starts to drift up linearly with γ.

It also assumes the draft distribution is close to the target. On tasks where next-token entropy is high. long division, multi-step symbolic reasoning, generating UUIDs, picking arbitrary but correct API parameter names. the draft model is wrong often, τ drops toward 1, and you are paying draft cost for nothing.

And it assumes you have spare FLOPs for the draft. On a fully batched serving stack where every FLOP is already going to target tokens, the draft is pure overhead. The break-even point is roughly batch size < 8 for chat traffic, and closer to batch size < 2 for code completion traffic.

Why this mattersThe default mode for code agents and reasoning chains should be speculative OFF, with a router that flips it on only for chat-style conversational blocks. Most teams ship the opposite and lose 15% throughput.
Common Confusions

Four things people get wrong

"Speculative decoding is just an approximate method that occasionally degrades quality."
No. The standard version is mathematically lossless. the output distribution is identical to greedy or sampling from the target alone. Approximate variants exist, but the original Chen and Leviathan papers, and every mainstream engine (vLLM, SGLang, TGI), ship the lossless version by default. If your outputs changed, you are using approximate decoding, not the standard algorithm.
"The draft model needs to be trained on the same data."
Not exactly. It needs the same tokenizer and roughly the same distribution. In practice people train a small model on a distilled version of the target's outputs (EAGLE does this), or use a smaller sibling from the same family (Qwen3-1.7B drafting for Qwen3-8B). A randomly chosen 7B model drafting for a 70B Llama will work but will have low τ because its distribution diverges.
"Bigger γ always helps."
No. γ = 3 to 8 is the usual sweet spot. Past γ = 8, the probability that all proposed tokens are accepted drops fast, so the marginal draft cost grows faster than the marginal accept count. Memory pressure from KV cache writes for the γ tokens also rises. Engines like vLLM default γ = 5 for chat and let you tune per workload.
"Speculative decoding cuts training cost too."
No. It only helps inference. Training already runs in large parallel batches and is throughput-bound, not latency-bound. The chain dependency that hurts inference is hidden by gradient accumulation in training. If you are optimizing training cost, look at FlashAttention, ZeRO sharding, or sequence parallelism. not speculative decoding.
Where To Go Next

Three specific places to dig deeper

  • PAPER · LOSSY-FREE FOUNDATION
    Leviathan, Kalman, Matias. Fast Inference from Transformers via Speculative Decoding (ICML 2023)
    The original paper. Read section 3 for the rejection-sampling proof that the output distribution is preserved. It is six pages and it is the math you wish someone had shown you the first time. arxiv.org/abs/2211.17192
  • TUTORIAL · STAFF-LEVEL DEEP DIVE
    Speculative Decoding: How It Evolved, When It Stays Lossless, and What's Next. NeurIPS 2026 Education Track
    Walk through the math, run four generations of draft models against Qwen3-8B, and measure τ yourself. Includes a Losslessbench that checks the output distribution bit-for-bit. This is the single best end-to-end resource right now. neurips2026-speculative-decoding.vercel.app
  • HANDS-ON · SHIP IT YOURSELF
    vLLM's --speculative-model flag, with EAGLE-3 or DFlash
    Spin up vLLM, point --speculative-model at a pre-trained EAGLE-3 or DFlash draft for your base model, and measure tokens/second on a representative prompt set. Most teams see a 2x–3x lift on chat traffic within an hour. The flag is one line; the evaluation rig is the hard part.
