Day 2 · Linear attention

Gated DeltaNet: kill the KV cache, keep the math

A single fixed-size state matrix per attention head, updated by a rank-one correction every token. That is the trick that powers Qwen3-Next, Kimi Linear, and Kimi K2 Thinking.

  • Why softmax blocks a recurrence and how to remove it
  • The delta rule: write the error, not the value
  • Why the gate matters, and what it controls
  • Recurrent decode vs chunkwise prefill, side by side
The model in one sentence

Replace store every past key and value with store one matrix that learns the map from keys to values.

Gated DeltaNet keeps a single fixed-size S per layer per head and updates it every token with the rank-one correction that brings the prediction at the new key toward the new value, then multiplies the whole state by a learned per-channel decay so old memories fade in proportion to how long ago they arrived.
The mental model

One matrix, one rule, one knob

The whole architecture reduces to two operations applied to a square matrix S:

Figure 1 · The full per-token update in two operations: gate, then rank-one correction.

S is a d_k x d_v matrix (head dim of key space by head dim of value space, typically 128 x 128). It is the entire memory for one attention head in one layer. No list of past tokens. No growing cache. Every read is just k_t · S_t, every write is the small correction shown above.

The walkthrough

Five moves from softmax attention to Gated DeltaNet

1. Softmax blocks the recurrence

Standard causal attention writes output_t = sum_i softmax(q_t . k_i) . v_i. Every token needs every past key, because the softmax denominator depends on the current query. That is why you cache the keys and values: you cannot fuse them into one number.

The cache is the price of selectivity. Drop it and you lose the model's ability to say pay attention only to this part of history.

Figure 2 · Every new query touches every past key. The cache is the bottleneck.

Why this matters

Long-context inference is gated by HBM bandwidth, not FLOPs. Reading a 1M-token KV cache for one query reads a million vectors. That is the memory wall linear attention exists to break.

2. Drop softmax, get a recurrent state

Drop the softmax and the per-query normalization. You are left with output_t = sum_i (q_t . k_i) . v_i. Rearrange: q_t . (sum_i k_i v_i^T). Everything about the past fits into one matrix S = sum_i k_i v_i^T. Update it every token with S := S + k_t v_t^T.

You just got a recurrence that runs in O(d x d) per step regardless of context length. The cache shrunk from a list of vectors to one matrix.

Figure 3 · With softmax gone, the past collapses into one matrix. Read is a single matvec.

Why this matters

This is the same trick MLA used for memory: a low-rank projection per token. Here it is even more aggressive. Every past token contributes one rank-1 column to S instead of one full key and value vector to the cache.

3. The problem: addition is not assignment

Plain linear attention writes S := S + k v. Read the new state with the same key: it returns v plus whatever the old state already returned. Write the same pair twice and the read doubles. Keys are not orthogonal, so writes interfere with prior writes. The memory becomes a corrupted running sum.

The fix is to ask the memory what it currently thinks k_t maps to, then write only the error.

Figure 4 · Same key written twice. Left: read doubles. Right: read is correct.

Why this matters

This is exactly one gradient step on the reconstruction loss for the linear map S at the current key. Treat each token as one online training example and you fall out of the same update.

4. The gate controls lifetime

DeltaNet fixes the write but not the lifetime. Without a forgetting mechanism, an early value sticks around and pollutes reads indefinitely. The fix is a per-channel decay alpha_t in [0,1]^d, learned as alpha_t = exp(-softplus(log_decay_t)), multiplied onto the state every step: S := diag(alpha) . S.

This is what turns plain DeltaNet into Gated DeltaNet. alpha close to 1 means long-lived memory, close to 0 means forget quickly. Different channels can have different lifetimes in the same head.

Figure 5 · Different channels, different lifetimes. One head, many memory horizons.

Why this matters

The gate is the only place where Gated DeltaNet differs from GLA (Gated Linear Attention) by Mamba. They share the recurrence and the gate; they differ in what the memory cell stores. KDA is Gated DeltaNet applied to a key-value map.

5. Two schedules for the same recurrence

During training and prefill, every token is known at once. Compute in chunks of 64-128 tokens: within a chunk use the parallel form (Triton tensor cores), between chunks use the recurrence. This is chunkwise Gated DeltaNet.

During decode, only one token arrives at a time. Use the recurrent form (one rank-one update, one matvec read). The state is the only thing carried between steps.

Figure 6 · Same recurrence. Different execution schedule. They produce identical results up to floating point.

Why this matters

The state is the only thing that crosses a chunk boundary. If you have a 100B-parameter model serving millions of users, the state per request is one matrix per layer per head. That is the entire memory footprint of attention during decode.

Common confusions

Four things people get wrong

01

"Gated DeltaNet is just an RNN with extra steps."

The recurrence is RNN-shaped, but the contents of S are not a hidden state. They are a learned linear map from keys to values. Reads are linear-algebraic lookups, not summed activations. The delta rule and the gate make the map associative and forgetting without losing that property.

02

"Removing the cache means the model has no memory."

The cache is gone but the state is the memory. It is just packed denser: every past token contributes a rank-1 slice of S, and the gate controls how long each slice survives. The total information budget is roughly d_k * d_v per head per layer, not context length.

03

"Linear attention is always faster than FlashAttention."

Per-step latency is great because reads are O(d·d). Training-time FLOPs are higher than softmax attention because you cannot reuse the same fused kernels for the recurrence. The chunkwise scheduler pays a fixed overhead per chunk. Choose linear when decode latency or KV cache memory dominates your serving cost.

04

"The state size grows with the model."

It grows with the head dim, not the model dim. Each head has its own d_k x d_v matrix. For a typical 48B Kimi Linear with head dim 128, the state is about 64KB per layer per head. Across 27 layers that is 1.7MB per request. That is the entire attention memory budget at any context length.

The paper that introduces the gate. Adds per-channel decay to the delta rule, evaluates on language modeling and retrieval, reports the recurrent/chunkwise equivalence.
